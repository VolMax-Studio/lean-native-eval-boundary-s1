# Diagnostic grammar and CLI pins — static source evidence

OBSERVED: the retrieved Message.lean files from all three pinned commits implement optional `(name)` after severity and optional `-endLine:endCol` after the start position. SerialMessage.toString routes warning/error through this formatter; information messages are emitted as their data without a location header.

Static call chain: src/shell/lean.cpp calls lean_main; src/util/shell.cpp parses CLI arguments and invokes run_shell_main; src/Lean/Shell.lean passes its jsonOutput and leanOpts into Elab.runFrontend; Frontend calls SnapshotTree.runAndReport; Language/Basic.lean reportMessages obtains printMessageEndPos from options and calls msg.toString includeEndPos on the non-JSON path. Shell defaults jsonOutput to false and processes -D through setConfigOption. No Lean invocation was needed to inspect this chain.

Message.lean lines 31–42 and 608–621 are the formatter and serialization evidence in all three versions. Language-Basic.lean lines 298–352 (v4.32.2), 396–450 (v4.33.1 and rc1) define printMessageEndPos, maxErrors and reportMessages/runAndReport. Shell.lean routes to runFrontend at 554–555 (v4.32.2) and 552–553 (v4.33.1 and rc1). Frontend calls runAndReport at 311 (v4.32.2) and 341 (v4.33.1 and rc1).

Registered text profile: no --json, no severity override flags, explicit `-D printMessageEndPos=false` and `-D maxErrors=0`, fixed input basename PoC.lean. Both streams are captured separately as UTF-8 bytes; no color or text-normalizing wrapper is permitted. Recognition additionally supports optional end positions so the source grammar is not mistaken for unrelated failure. A particular native_decide diagnostic's name or runtime output remains unmeasured. The classifier's structural rule is defined from sources and synthetic inputs, not a trial run.

The registered parser accepts `FILE:L:C[-EL:EC]: error[(NAME)]: BODY` and equivalent warning headers. It recognizes error markers independently of a valid positioned header: an orphan or malformed error cannot pass acceptance or expected rejection. Named labels contain no parenthesis/newline; unusual escaped names outside this bounded grammar lead to insufficient evidence, never acceptance when an error marker is recognized. The literal no-diagnostic-error condition is implemented across both streams, not just plain `error:`.
